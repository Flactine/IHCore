# 加密 MIX（v1）

独立工具使用 Windows CNG AES-256-GCM，将整个原始 MIX（含索引）分块加密。IHCore 以只读文件流提供解密后的字节，不生成明文临时文件。此功能提高普通解包的门槛，无法阻止逆向 DLL、内存提取或运行时截获。

## 使用

1. 在 Visual Studio Developer Command Prompt 中运行 `tools\IHMixCrypt\build.cmd`。输出为 `tools\IHMixCrypt\bin\IHMixCrypt.exe`。
2. 生成密钥（或自行准备包含 64 个十六进制字符的文本文件，无 BOM，可有末尾换行）：

   ```bat
   IHMixCrypt keygen mod-key.txt
   ```

3. 生成编码后的私有密钥头文件（覆盖指定输出头文件），然后编译私有 Release Win32 IHCore：

   ```bat
   IHMixCrypt embed-key mod-key.txt IHCore\EncryptedMixKey.h
   ```

   在仓库根目录执行，或使用绝对路径。不要再手工填写 `KeyHex` 明文字符串。一个构建使用一个主密钥；使用原密钥生成头文件不需要重新加密已有 MIX。生成头文件包含随机掩码、置换后的编码字节和运行时还原函数，避免 DLL 内直接出现可读的密钥字符串。这是混淆，不是无法逆向的密钥保护。`embed-key` 会覆盖输出文件，请勿将输出路径设为密钥文件或其他资产。
4. 加密并检查：

   ```bat
   IHMixCrypt encrypt original.mix expandmd99.mix mod-key.txt
   IHMixCrypt verify expandmd99.mix mod-key.txt
   ```

   输出必须不存在，防止误覆盖源素材；失败可能留下不完整输出，请检查错误后手动清理。工具只封装字节，不检查输入是否为合法 MIX；先确保原文件能被游戏加载。密钥通过文件读取，不作为命令行参数传递。
5. 将输出保持 `.mix` 扩展名，放到游戏正常加载的路径，使用包含相同密钥的 IHCore。仍须启用现有 `EnableCustomFile` 功能。自动加载命名规则及自定义 MIX 加载配置照旧。

不要随 MOD 发布密钥文件、填有密钥的源码或调试符号。先用普通 MIX 验证资源正常，再替换为加密版本。

## 支持范围与行为

- 在文件路径解析完成后识别魔数，支持磁盘 MIX 及现有额外目录搜索；普通 MIX 保留原流程。
- 支持原始长度 1 至 2147483647 字节，受游戏有符号 32 位文件接口限制。
- 支持随机读取、跨块读取和 EOF；每个流缓存一个 64 KiB 明文块。
- 密钥错误、头部损坏在打开/查询时失败；数据块损坏在访问该块时失败，错误写入游戏日志。`verify` 可在发布前验证全部数据块。失败不回退到把密文当普通 MIX 解析。
- 外层加密 MIX 中的普通嵌套 MIX 由已有偏移层处理；**不支持将加密容器作为另一个 MIX 内的成员再递归解密**。如需嵌套，先完成普通 MIX 打包，只加密最外层。
- 自定义流显式绑定优先于磁盘容器识别；`UseOriginalFileClass` 保持原有绕过语义。
- 本实现依赖 Windows CNG；旧 Windows/兼容层需要实际验证。

## 格式

所有整数为小端。64 字节文件头：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 | ASCII `IHMIXENC` |
| 8 | 4 | 版本 1 |
| 12 | 4 | 块大小 65536 |
| 16 | 8 | 原始长度 |
| 24 | 16 | 随机 salt |
| 40 | 8 | 随机 nonce 前缀 |
| 48 | 16 | 文件头 GCM tag |

每次加密重新生成 salt 和 nonce 前缀。文件 AES 密钥由主密钥经 PBKDF2-HMAC-SHA256（10000 次、salt、32 字节输出）派生；主密钥应为随机 256 位密钥，不应使用弱口令。

数据区按顺序存放 `[密文块][16 字节 tag]`，最后一块按实际长度存储。nonce 为 8 字节前缀和 4 字节小端块号；AAD 为文件头前 48 字节及块号。文件头自身使用块号 `0xffffffff` 对空消息认证，数据块号从 0 开始，大小限制确保不与保留号重叠。验证严格检查容器总长度。

## 验证

```bat
IHMixCrypt selftest "%TEMP%"
```

覆盖 1、65535、65536、65537、196741 字节文件、随机及整文件读取、EOF、错误密钥、头/密文/tag 篡改、截断和尾部多余字节。

已在本机通过上述测试，并使用 MSVC x86 单独编译 `EncryptedMix.cpp` 和 `ExtCD.cpp`。默认完整构建在现有 `YRMemory.h` / `IH.Ext.h` 模板代码遇到新版 MSVC 严格模式兼容错误；未更改这些既有模板。尚未进行游戏内验证。

游戏验收建议：原版 MIX 与加密 MIX 分别启动并进入地图；检查图片、体素、音频及普通嵌套 MIX；测试额外目录；换错密钥、破坏数据后确认加载失败并有日志。不能仅以工具测试通过视为游戏兼容性验证完成。
